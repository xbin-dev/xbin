Personal tiles: capability requests (net, containers, ports) need a workspace admin. Org-owned: the org's admins can approve within their allowance.

Fork an existing tile: copies its code (git history included — the repos stay related), rewrites references to the old path, and registers an independent tile. Secrets and stored resource data don't come along; cross-scope grants need your approval again. Nor do tile deployments: the copy is the source's work tree, even where its primary runs a pinned checkpoint, and it starts with live reload on.

Templates are blueprints — pick one and give it a name to stamp out an independent component you own and can build up. Builtin and any workspace component marked as a template both show here.

Install a component from a git remote — GitHub, GitLab, or any git URL. It's cloned in as its own repo, so its origin remote makes it updatable later.

Newer versions of builtin components (the shell, manager/admin tiles, imported tiles) that shipped with this xbind. Replace takes the new version (discarding local edits); Propose as PR files the update as a change proposal the tile's own terminal/agent reviews and merges — the recommended path when you've customized it. Merge writes 3-way conflict markers straight into the files (legacy; everything is in git, so it's recoverable). Template instances are yours and aren't tracked.
