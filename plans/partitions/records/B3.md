## Changelog entry (docs/changelog.md, under the merge date)

```markdown
- **llm-gw counts usage per person's partition** (llm-gw's API.md
  "Partitioned callers", [partitions.md](/docs/partitions.md) §Providers).
  A call from a partitioned tile — every agent instance made from the
  template now is, by default — is counted per caller: the calling tile,
  its deployment and the person's partition (`X-XBin-Partition-Id`; the
  tile's global instance is its own row), with requests, tokens, cost and
  the last use — metadata only, never a prompt, answer or model. The tile's
  page shows them under **usage by partition**: every row to a manager of
  llm-gw (write or terminal access) and the owner, their own partitions'
  rows to anyone else who opens it, none while viewing the workspace as
  someone; `GET /stats` gains `callers` (only once a partitioned tile has
  called); `GET /metrics` stays per backend, so a metrics reader never
  learns who used what. An optional **fairness limit** (`PUT /config
  {partitionLimit}`, 0 = off, the default; up to 64; write access) caps how
  many calls one person's partition may have in flight — more wait their
  turn, in order; other people's partitions, the global instance and tiles
  that aren't partitioned are never held. A tile that isn't partitioned is
  counted exactly as before, and until a partitioned tile calls nothing on
  the page or in the responses changes. Update the tile (`bx builtin
  update tile:llm-gw`, v8) to get it.
- **Builtin tiles around a partitioned agent: the docs**
  ([agent-inbox.md](/docs/agent-inbox.md) §A partitioned agent,
  [partitions.md](/docs/partitions.md) §Providers). Adapters (the agent
  messaging bridge) and the webhooks tile aren't partitioned and always
  reach a partitioned agent's global instance, over the same contract: the
  global instance keeps channels, their rules and the links; a linked
  person's DM and an event for a person's private trigger are handed to
  that person's partition by partition mail, and replies come back through
  the global instance, which posts them where its own hand-off record says;
  a first DM waits for the person's partition to run once, with a notice;
  `runId`/`inboxId`/`sessionKey` in verdicts and outbox rows are
  informational; a webhook's `202` means taken, not run; a private push
  trigger needs a `match` no other person's overlaps. The bridge
  template's `AGENTS.md` and `API.md`, and the webhooks (v3) and
  sandbox-terminal tiles' `API.md`, say the same to their builders and
  people — including that binding them is an ordinary (global) bind, that
  a personal bind applies to none of them (they aren't partitioned), and
  who ends up in whose trust base. Nothing to change.
```

## Decision entry (plans/DECISIONS.md, the next free D-number)

```markdown
- **D<next> — Partitioned tiles, B3: llm-gw counts per person's partition;
  the tiles around a partitioned agent stay unpartitioned (2026-09-30).**
  Implements llm-gw's side of PD-36 and the notes of 09 §2-§5 of
  plans/partitions (bridge, webhooks, sandbox-terminal, llm-gw). llm-gw's
  API.md "Partitioned callers"; docs/agent-inbox.md §A partitioned agent;
  docs/partitions.md §Providers.
  - **Chosen.**
    - **Per-caller rows only for partitioned callers.** A call counts per
      caller when it carries `X-XBin-Partition` (xbind sets it on every
      call from a partitioned tile's principals); the key is (`X-XBin-From`,
      `X-XBin-Deployment`, `X-XBin-Partition-Id`) — partitions.md's
      provider rule, so `""` and `global` are one row and a person deleted
      and recreated starts a new one; the display name is the last call's
      `X-XBin-Partition`. A call from a tile that isn't partitioned carries
      neither header and counts per backend only: the kv, `GET /stats`,
      `GET /config`, `/metrics` and the page are byte-identical for a
      workspace without partitioned tiles (`callers` and `partitionLimit`
      appear only when there is something to say).
    - **Metadata only:** requests, tokens in/out, cost, last use; kept in
      the state kv's `callers` (at most 1000 rows, the least recently seen
      dropped past that), written after each counted call under one
      persist lock so the last write is the latest snapshot. Rows of calls
      in flight that haven't ended yet show with zero counts.
    - **Who sees rows:** the tile's managers (write/terminal, the owner
      token) all; anyone else on its page only rows whose partition is
      `user:<them>`; view-as none. `/metrics` stays per backend (a bound
      metrics reader would otherwise learn every person's activity).
    - **The fairness limit** (`partitionLimit`, 0 = off, default off,
      ≤ 64; changing it needs write access) caps one user partition's
      calls in flight per caller key; excess calls **wait** in FIFO order
      (bounded by the caller's own context — a caller that hangs up leaves
      the queue, and a slot handed to it as it left passes on) rather than
      answer 429: every caller keeps working, only slower. The global
      instance and unpartitioned callers are never held. A raised limit
      admits waiting calls at once.
    - **Bridge, webhooks, sandbox-terminal: no code change.** They stay
      unpartitioned and reach a partitioned agent's global instance; their
      docs say what B2c's hand-offs mean for them (09 §2-§4), that binding
      them is an ordinary global bind by today's authority (PD-54, D33,
      D88), that a personal bind doesn't apply to them, and who is in
      whose trust base.
  - **Not chosen.** Per-caller rows for every caller (a per-tile usage
    table in every workspace: useful, but not byte-identical — an owner
    question); a 429 for the fairness limit (callers would need retry
    logic; the agent has it, other tiles may not); per-partition series in
    `/metrics`; a per-day token budget (the counters make it a small
    follow-up if wanted).
  - **Fixed on the way:** llm-gw's per-backend `bumpStats` encoded its
    shared map outside its lock (a call adding a backend's first row could
    race another's persist: a concurrent map read/write); it now marshals
    under the lock.
```

## Deviations

- **The key includes `X-XBin-Deployment`** (09 §5 says per-(From,
  Partition-Id)): docs/partitions.md's provider rule is the triple, and a
  non-primary deployment runs as `global` — so the only difference is that
  a deployment's calls have a row of their own instead of adding to the
  global instance's.
- **Only partitioned callers get rows** (byte-identity for every
  workspace without a partitioned tile); an unpartitioned caller stays in
  the per-backend counters only.
- **The fairness limit waits instead of refusing**, and applies only to
  user partitions (never the global instance).
- **Rows are visible to a person for their own partitions** on llm-gw's
  page (09 §5 names only the counters; 08 §7 gives managers per-person
  totals): a person sees their usage, the tile's managers everyone's.
- **sandbox-terminal stays at v3** (B1's unreleased bump on `partitions`):
  its changelog line gains the API.md note and hack/tile-versions.txt was
  regenerated for v3, instead of a v4 for a doc-only change. webhooks goes
  to v3; llm-gw to v8.
- **W3a/W3b listed "B3 (docs) — fold the changelog and decision entries of
  B2a, F6, F7b and F17b"**: that fold landed before this pack
  (d6499604, D155–D158), and this pack's instructions forbid editing
  docs/changelog.md and plans/DECISIONS.md, so nothing of it is here.
- **The UI check lives in the tilePages pass** (a block at its end), not a
  new pass: shots.js is at its size budget, and the harness runs no
  partitioned caller, so the block seeds llm-gw's `callers` kv, restarts
  its backend (the channels pass's kill), checks the page and the limit's
  form, then removes the seed.
