# F3 — records for the integrator

Work pack F3 (runner, plans/partitions/03 §A) of the partitioned-tiles
plan, branch `pt/f3`. The integrator folds the two entries below into
`docs/changelog.md` and `plans/DECISIONS.md` (this pack edits neither), and
wires the seams listed after them when F2 and F4 merge.

## Changelog entry (docs/changelog.md, under the merge date)

```markdown
- **Partitioned tiles: people's instances in the runner, and their limits
  — in development** ([partitions.md](/docs/partitions.md) §How people's
  partitions run, [protocol.md](/docs/protocol.md)). xbind can now run one
  backend per person of a partitioned tile beside its global instance:
  started on the person's first use and never at boot, stopped 10 minutes
  after its last use (an open event stream doesn't count), only on the
  tile's primary and only with `--isolate`, each with its own socket, token,
  log, cgroup and data, `XBIN_PARTITION=user:<id>`, and a non-primary
  deployment's network (relayed egress under the tile's policy; no host
  network, provider splice, ingress or stream-slot dials). The global
  instance is today's process at today's keys with `XBIN_PARTITION=global`;
  `alwaysOn` keeps it alone up, and a `["user"]` tile never runs it. A code
  change builds once and restarts people's running instances onto that
  build. People's instances are capped per tile and workspace from host
  memory (503 `too many people's instances of <tile> are running; try again
  shortly` past the cap when nothing idle can be stopped); the new admin
  route `POST /api/xbin/partitions/limits {tile?, maxRunning?,
  partitionBytes?}` sets the caps and a tile's per-person byte ceiling, and
  a tile manager may lower their own tile's. `/api/xbin/sandboxes` rows of a
  person's instance carry `partition`. People's partitions start once the
  routing and data planes land; until then nothing changes for any tile,
  and a tile without `partition` is unchanged, byte for byte.
```

## Decision entry (plans/DECISIONS.md, the next free D-number)

```markdown
- **D<next> — Partitioned tiles, F3: people's partitions in the runner
  (2026-09-30).** Implements PD-04 (the global instance at today's runner
  keys), PD-17 (user partitions on the primary only), PD-18 (caps from
  memory, admin-settable; LRU eviction of what isn't in use; passive
  streams don't count; background starts never evict, ≤ 4 at once, mail
  ≤ 6/min per tile; the 10-minute idle stop, global exempt), PD-19 (no
  user partition without `--isolate`), PD-28's network half (user
  partitions get the non-primary rule), PD-35's coverage items (hidden-tab
  streams passive, idle stop, no boot starts, one global per instance) and
  PD-46's metadata rows, of plans/partitions/90-decisions.md; the design is
  plans/partitions/03-runner-data-vault.md §A.
  - **Chosen.**
    - **A map of its own.** A person's state is keyed
      `partStateKey(tile, dep, pkey)` = stateKey + "\x00p\x00" + pkey, in
      `Runner.parts.states` apart from today's states, so nothing that walks
      today's (Status, stats, alwaysOn, D127q admission, VMs, the ingress
      dial) meets one. Stops, the reaper, Stop/StopAll, envKeep and the
      inspect rows learn it explicitly.
    - **A copy of the view names the partition.** A generation spawns from
      a copy of the primary's view with `Component.Partition`/`PartitionID`
      set (views are shared; the registry never sets them). Every spawn-time
      decision reads it: run dir `p-<16 hex>`, log
      `.xbin/partition/<TileKey>/<dep>/<pkey>/backend.log`, cgroup leaf
      `tile-<key>/p-<hash>/backend` (the tile's caps per person), token
      through `RegisterPartitionInstance`, env through `PartitionEnv`, data
      binds from its remap (never a path at itself on main), and
      `UserPartition()` for the network rule in launchSpecWith, netPlanFor,
      spawnEgress, ingressFwd and hostDialFor.
    - **XBIN_PARTITION** is set by the runner: `user:<id>` for a person's,
      `global` for the primary of a tile running user partitions and for a
      non-primary deployment whose own code asks; right after XBIN_COMPONENT
      (after XBIN_DEPLOYMENT when that is set); never on an unpartitioned
      tile (the env golden).
    - **Fail-closed hooks.** Identity (pkey/uid), liveness, env/data, token
      binding and event routing are PartitionHooks; while any start hook is
      nil no person's partition starts (ErrPartitionRefused), and a nil
      event hook drops a partition's runner events instead of publishing
      them tile-wide.
    - **The runner's running mode comes from the registry hook.**
      `Registry.OnPartitionChange` calls `PartitionsChanged(c, old, new)`
      (running specs: Recorded while Partitioned, else none) before the scan
      is published; the runner records the spec it answers from at once, so
      no request between the hook and the publish sees the old mode. It
      revokes and stops people's instances without user partitions, and
      stops (never starts) the primary's generation whose env or existence
      changed — the hook may name a tile the scan dropped.
    - **A user-only tile never runs its primary**: startFor refuses it on
      every path (lazy start, deploy, restart), ensurePrimary refuses early,
      alwaysOn skips it, and a deploy to it prepares and commits without a
      generation (deployIdle) and moves people's partitions.
    - **One build per change.** The primary's work-tree build of a
      partitioned tile goes through a flight keyed by a per-tile build
      sequence, which Changed and every work-tree deploy advance (before the
      primary's own rebuild starts); every instance started for that change
      reuses its bin — or its error, sticky as today. Checkpoints were
      already shared. Changed restarts live partitions ≤ 4 at a time; a
      successful Deploy/Restart of the primary does the same.
    - **Limits** live in `data/partition-limits.json` (not under
      `data/partitions`, so a switch's wipe never takes them): an admin's
      workspace cap and per-tile cap and byte ceiling, a manager's lower
      ones beside them; effective = the lower; POST refuses a manager's
      raise (403), the tile's own credentials (403), an unknown tile (404,
      after the auth check); a file that can't be read gives the defaults
      and POST 500s without overwriting. The runner reads it through
      `PartitionCapsFor`, the data plane through `Broker.PartitionBytes`.
  - **Not chosen:** partition states in today's map (every walker of it
    would have needed a filter; a missed one would count a person's
    instance as the tile's primary); starting the primary from
    PartitionsChanged (it runs under the scan lock, possibly for a removed
    tile); the flight for every tile (would change the zero state's rebuild
    on each restart).
```

## Deviations and open ends

- **Reassign stops people's partitions** instead of restarting them (03
  §A.7): their state is keyed by the old primary, and F1 refuses moving a
  partitioned tile's primary anyway; they start again on the new primary on
  their next use.
- **PartitionsChanged stops, never restarts,** the global instance whose
  env changed (turned partitioned/unpartitioned) — it runs under the scan
  lock and may name a removed tile. The next request or alwaysOn's wake
  starts it with the right `XBIN_PARTITION`.
- **Eviction and stops forget the state** (the next use starts a fresh
  one); the reaper keeps it dirty, as today's.
- **"In use"**: an active (non-passive) tracked connection or an
  interactive request in the last 2 minutes; an engine hold is an active
  connection. The idle stop counts any non-passive use (a cron delivery
  included), per 03 §A.6.
- **Background start limit is non-blocking**: past 4 in flight a background
  start is deferred at once rather than queued.
- **Limits apply at the next start**; lowering a cap doesn't stop running
  instances. `partitionBytes` is stored and served (`PartitionBytes`) but
  enforced by F4.
- **The xbind-level isolated tests** (test/isolated: two people's agent
  partitions' `XBIN_RES_*` files, a `"read"` filesystem read-only) need
  F2's routing and F4's volumes; this pack's host-net test runs at the
  runner level under `-tags=integration`
  (`TestPartitionHostNetIsolated`), which `make integration` includes. I1
  owns the xbind-level versions.
- **XBIN_PARTITION is set by the runner** (03 §A.4), not by F4's
  PartitionEnv as records/F8.md assumed; this pack documents it in
  docs/protocol.md §Backend contract and docs/partitions.md. The rows F8
  assigns to F2 (docs/elements.md's and docs/overview/16-extending.md's env
  tables) are still to add — whichever of F2/F4 lands last should not add a
  second backend-contract bullet.
- Moved `SetBuiltins`/`SetBuiltinTemplates`/`SetUpdater` from
  internal/broker/broker.go to builtins_set.go, unchanged, to make room
  under the 800-line cap for the limits store's field and registration.
- The sandboxes view samples a person's partition by its own leaf (stats
  scope `partition`).
