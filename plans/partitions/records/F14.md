## Changelog entry (docs/changelog.md, under the merge date)

- **Partitioned tiles: the shell's marker, and Keep / Switch on a paused
  tile** ([partitions.md](/docs/partitions.md) §The mode). The workspace
  shell marks a tile whose recorded mode has user partitions with a small
  teal disc, half filled — on its sidebar row, before ⋯, and in place of
  the runtime dot on its window head — whose tooltip reads "Partitioned:
  each person here has their own data" (and names the global instance when
  the tile has one). It marks a state, it isn't a button, and a pending
  switch doesn't change it; a theme may set its colour with the `--bx-part`
  token. While a partition mode switch is pending, the tile's window greys
  out under the request's words (its `/alerts` message), and a tile
  manager decides right there: **Keep the current mode** (the tile runs
  again, nothing is deleted), or **Switch and delete all data…** —
  **Switch…** when only `"global"` comes or goes — which shows what the
  switch deletes (the dry run's counts: namespaces, people's partitions,
  vault keys, registrations, bytes, backup keys) and keeps, and asks for
  the tile's path before it calls `POST /api/xbin/partitions/mode`. People
  who can't decide see who can. A window showing another deployment of the
  tile isn't paused and isn't greyed out. The shell is scaffold: existing
  workspaces get this with `bx builtin update scaffold:shell`; an older
  shell keeps showing the top banner and xbind's page in the frame. Tiles
  that never ask for `partition` look exactly as before. Nothing to change.

## Decision entry (plans/DECISIONS.md, the next free D-number)

- **D&lt;next&gt; — Partitioned tiles, F14: the shell's marker (design A)
  and the pending card's Keep / Switch (2026-09-30).** Implements PD-53 as
  the owner ruled it (H2: A, the teal half-split disc), the shell half of
  PD-47's scaffold surfaces and 06 §12.3's card overlay, deciding through
  F13a's route (D145). Design: plans/partitions/06-terminals-ops.md
  §12.2-§12.3, 01 §2.4; docs/partitions.md.
  - **Chosen.**
    - **One lit-free module owns the words and the decision**
      (`workspace-template/shell/partition-mode.js`): what a row's
      `partition` reads as (`partitionView`: state, recorded mode,
      request, pending, declined), the marker's tooltip, the pending
      card's text (the `/alerts` `partition-switch` message when the shell
      has it — xbind's words, as the banner shows them — else the same
      facts from the row), the POST bodies (from/to exactly as the row
      showed them, `null` for unpartitioned, so a changed request is
      xbind's 409, never a blind decision), the typed confirmation's
      `<bx-dialog>` spec from the dry run's answer, and what the dialog's
      answer asks for. `hack/partition-mode.test.mjs` runs it in node;
      the registry's `TestShellSwitchWords` pins its switch words and mode
      names to `registry.SwitchDeletes` / `PartitionSpec.String`.
    - **The marker follows R, not the request**: shown whenever the
      recorded mode has user partitions (partitioned, pending, invalid
      alike) — a pending switch doesn't change it (06 §12.2). An 8px SVG
      ring with its left half filled, `role="img"`, the tooltip as
      `title` and `aria-label`, `cursor: default`, no border, no hover
      rule. `shell-kit.js partitionMark(c)` returns `null` for every other
      row, so the head falls back to the runtime dot and the row draws
      nothing (an xbind without partitions, a tile that never asked).
    - **The hue**: `--bx-part-c: var(--bx-part, #3fb5a3)` on the elements'
      hosts, and, where `light-dark()` is supported, `var(--bx-part,
      light-dark(#1f8778, #3fb5a3))` — the workspace theme is dark
      (`color-scheme: dark`), a theme that makes the page light gets the
      deeper teal (≥3:1 on white). No token is added to `theme.css`
      (setting it there would pin the dark value for every scheme).
    - **The overlay** (`bx-canvas.js _partOverlay`) sits over the card
      body only — the head stays live (menu, terminal, close, drag) — and
      only on a window showing the primary (another deployment isn't
      paused). Buttons for the viewer `canAdminTile` passes (the ⚙ rule:
      workspace admin, the tile's user owner, an admin of its owning org —
      the same set as `mayManageTile`); everyone else reads who decides.
      xbind still judges every call (a view-as session, a race: the
      refusal shows in the card). Calls are the person's raw `fetch` (the
      shell tile's `xbin.fetch` would be a tile principal, which never
      decides). Keep posts at once. Switch… posts the dry run first, then
      opens the typed confirmation; a wrong path, or the C12 "Switch
      anyway" box unticked while the dry run named sandbox managers that
      lack `partitions`, re-asks in the dialog without a call; a refusal
      (409 managers, 500 part-way, a stale request) re-opens the dialog
      with xbind's error and the typed path kept. Each card's decision
      state is keyed by the request (R → Q), so a new request never shows
      an old answer. After a decision the shell reloads `/components` and
      `/alerts` at once (F13a's `reload` event does it too).
  - **Not chosen:** a second "partition chip" element beside the marker
    (design A's case is "no new element in the head"; the chip is the
    marker, its tooltip naming the global instance); the shell's own
    `_dialogs` stack for the confirmation (bx-shell.js sits at its size
    budget; bx-canvas renders its `<bx-dialog>` beside its ⇈ menu — the
    backdrop still covers the whole page); Switch… on a *declined* tile
    (06 §12.3 asks for the overlay on pending tiles; `bx`, the admin
    section and `/xbin/partitions` offer it); a light theme in `theme.css`.

## Deviations and notes

- **The "partition chip" is the marker.** The pack's line "the partition
  chip (tooltip: partitioned — each person has their own data; global: also
  a shared instance)" is read as the marker's tooltip: "Partitioned: each
  person here has their own data" and, with `"global"`, "…; one shared
  global instance also runs, for what isn't a person's". No separate chip
  element.
- **The resize corner moved up**: `.gtile .rz` `z-index` 3 → 12, so the
  corner stays above the overlay (11) and bx-frame's build-error overlay
  (9, which covered it before this change too). The overlay sits above
  bx-frame's own overlays so a build error can't hide Keep/Switch;
  terminal pop-ups (z ≥ 2001) stay above it.
- **bx-shell.js**: one existing line gains `.alerts` and `.reload` for
  bx-canvas (the file is at its size budget, 1891/1892 lines, unchanged).
- **docs/partitions.md**: the marker paragraph (before "Who reaches which
  partition"), the shell bullet under "Where it shows", "Managers decide in
  the shell, …", and the TODO list keeps only the shell's consent prompts.
  docs/maintenance.md's shell section names `partition-mode.js`, its test
  and the harness pass.
- **The old-shell pass**: F13a's `partitionSwitch` (unchanged) passes
  against this shell (12 PASS); `workspace-template/shell/` is the only
  scaffold touched, so a workspace that hasn't taken `bx builtin update`
  keeps its shell byte for byte.
