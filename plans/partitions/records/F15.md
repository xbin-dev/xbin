# F15 — records for the integrator

Work pack F15 (bind types: global binds under today's authority, personal
binds; plans/partitions/05 §3) of the partitioned-tiles plan, branch
`pt/f15` on `partitions` at 982718a3. Implements **PD-16** and **PD-54**
(owner ruling 2026-09-29: a global bind follows today's bind authority,
partitioned or not). The integrator folds the two entries below into
`docs/changelog.md` and `plans/DECISIONS.md` (this pack edits neither).

## Changelog entry (docs/changelog.md, under the merge date)

```markdown
- **Partitioned tiles: global and personal binds — in development**
  ([partitions.md](/docs/partitions.md) §Bind types,
  [protocol.md](/docs/protocol.md) `/partitions/binds`, `POST /bindings`
  and the backend env, [elements.md](/docs/elements.md) interfaces,
  [bx.md](/docs/bx.md) `bx bind --personal`). A partitioned tile's
  bindings are **global binds**: made as today, by whoever may bind them
  today (a workspace admin, an org admin within their org, a personal
  tile's owner within their allowance), and seen by every person's
  partition and the global instance; the admin console's Interfaces
  (wiring) view labels them *global*. New: a **personal bind** — the owner
  of a personal tile wires it into their **own** partition of a partitioned
  tile they can read, on a `"multi": true` http slot, with their own sign-in
  (never from a tile's terminal): `bx bind --personal apps/agent
  mcp=users/alice/mcp`, or `POST /api/xbin/partitions/binds {requester,
  slot, provider}`. Only that person's partition instance lists it in
  `XBIN_IFACE_<SLOT>`, and only their frames in `xbin.iface(slot)`, each
  row with `personal: true` after the global rows; it lets a call through
  only from that partition, while they still own the provider — anyone
  else gets the same 403 as if nothing were bound. Adding or removing one
  restarts only that person's instance. `GET` lists your own (admins:
  everyone's, with `live` and `why`), `DELETE` removes one (its person or an
  admin); a personal bind also goes when its provider changes owner, its
  person is deleted, or the tile switches between user partitions and
  unpartitioned. One refusal is new for every workspace: binding an
  unpartitioned tile's http slot to a partitioned tile without a global
  instance answers 409 (no call of it could reach that tile); a ref the
  slot already holds is never judged again. Nothing else changes for a
  tile that isn't partitioned.
```

## Decision entry (plans/DECISIONS.md, the next free D-number)

```markdown
- **D<next> — Partitioned tiles, F15: bind types — global binds under
  today's authority, personal binds in xbind state (2026-09-30).**
  Implements PD-16 and PD-54 of plans/partitions/90-decisions.md (owner
  ruling 2026-09-29: today's bind authority, partitioned or not); the
  design is plans/partitions/05-fabric-edges-global.md §3.
  - **Chosen.**
    - **Global binds are today's.** `apiBindingSet`, the delegated paths
      (D26/D33 org admins, D88 personal owners) and `grantMutation` are
      unchanged for a partitioned requester: the people who can bind a
      provider into every partition could change the shared tile's code
      anyway (PD-23). The one addition is a bind-time refusal (05 §1): a
      **new** ref of an **unpartitioned** requester's http slot to a tile
      whose recorded mode has user partitions and **no global** instance is
      409 (`bindConflict`; Route would refuse every call). A ref the slot
      already holds is not judged again, so a multi slot holding a ref to a
      tile that later partitioned stays editable (never break users).
    - **Personal binds are xbind state keyed by uid.**
      `data/partitions/binds/<uid>.json` = `{schema: 1, user, uid, binds:
      [{id, requester, slot, provider, at}]}` (0600, atomic writes). A
      person's record is read only through their **stored** uid (never
      minted on a read), so a deleted person's record, or an earlier
      incarnation's, applies to no one (PD-43), and older binaries never
      read it (PD-46).
    - **Who creates one.** `POST /partitions/binds` is **PersonOnly** (the
      partition class): a person's own session, app or device — never a
      tile principal, view-as or the root token. The handler checks: the
      caller owns the provider (`Owner(provider) == user:<id>`, 403 — an
      admin binding someone else's tile included), can read the requester
      (`personLive`, 403), the ceiling allows the edge (403); the requester
      is partitioned and not paused, the slot is a multi http slot, the
      provider isn't partitioned and provides the slot's service as a plain
      provider (no `#instance`, v1), and isn't already bound on the slot for
      everyone (409). The uid is minted at the person's first bind.
    - **Seen by one partition.** F4's `partitionIfaceEnvSeam` appends the
      person's live binds to each multi slot's `XBIN_IFACE_<SLOT>` JSON as
      `{provider, url, service, personal: true}` after the global rows
      (user partitions on the primary only; the global instance's env never
      goes through the seam). The document meta: the server asks an
      optional `PartitionInterfacesPolicy` (`docInterfaces`, the only
      static.go change) for a partitioned tile's primary document viewed in
      a person's own user partition (as `partitionHead` resolves it); every
      other document gets `Interfaces` exactly. `IfaceEndpoint.Personal`
      (omitempty) marks the rows.
    - **The call filter is live.** F2's `personalBindGrant` is
      `personalBindRole(from, callerPart, target)`: for a user partition
      only, its person's live record, a bind of `from` to `target` that
      still holds (`personalBindCheck`: requester partitioned, multi http
      slot, provider owned by the person, unpartitioned, providing the
      service, ceiling), granting that provide's role (first by slot).
      Route asks it only after `resolveTarget`'s `grantedRole` refused
      (`NotGrantedError`) a user partition's cross-tile call, so
      resolveTarget stays the single evaluation point
      (`TestEdgePolicyCallers`); together they are 05 §3's
      `grantedRoleIn`. Every other caller — another person's partition,
      the global instance, an unpartitioned tile, a guessed URL — keeps
      today's refusal, byte for byte.
    - **One partition restarts.** A create or delete restarts only that
      person's partition instance of the requester (`SetPartitionRestart` ←
      `Runner.StopPartition`, boot; the next request starts it with the new
      env) and publishes `grants` for the requester stamped with the
      person's partition, so only their sockets and frames reload.
    - **Lifecycle.** A provider transfer drops the rows of people who no
      longer own it and restarts their partitions
      (`executeTransferEffects` → `personalBindsProviderMoved`); a deleted
      person's record goes through `PersonalBindsUserDeleted(userID, uid)`
      (the users store's delete hook); the store `personal-binds` makes a
      tile with personal binds hold data (01 §2.2) and its wipe hook removes
      them on a switch between user partitions and unpartitioned, counted
      with the registrations and naming their people — adding or removing
      `global` keeps them (H1).
    - **Admins list and remove, never create for others.** `GET` answers a
      person's own rows, or every live person's for an admin (the admin
      tile included), each with `live`/`why`; `DELETE {id}` or `{requester,
      slot, provider[, user]}` by the person or an admin. The admin console's
      wiring view labels a partitioned tile's bindings *global* and lists
      its personal binds with a remove button.
  - **Rejected.**
    - Refusing the delegated paths (org admins, personal owners) for a
      partitioned requester (the plan's rev. 2): the owner ruled today's
      authority.
    - A `grantedRoleIn` replacing `grantedRole` inside resolveTarget: it
      would give the edge policy a second evaluation point; the personal
      half rides F2's seam instead.
    - Personal binds in the workspace manifest (PD-54: a person's wiring is
      their metadata; older binaries would read it as global).
    - Judging every ref of a slot on each edit (the 409 on refs bound
      before their provider partitioned would block unrelated edits).
```

## Deviations and open ends

- **The pack text vs the owner ruling.** 95's F15 entry still says
  "delegated.go/personal.go (delegated paths refused for partitioned
  requesters)", 05 §3's table says "admins only when the requester is
  partitioned", and 05 §Tests' first bind-types bullet expects 403 for an
  org admin's or personal owner's global bind — rev. 2 leftovers. PD-54 is
  DECIDED as today's authority (and 05 §3's prose, 90 §H and
  docs/partitions.md say so), so delegated.go, personal.go and
  grantMutation are untouched; `TestGlobalBindAuthority` pins today's rules
  on a partitioned requester instead. The "Global-bind narrowing" risk in
  95 is moot.
- **`grantedRoleIn` is two halves**, not one function (above):
  `TestEdgePolicyCallers` forbids a second `grantedRole` caller.
- **The 409** is judged on new refs only; `uses` grant approvals get no
  analogous refusal (Route refuses at call time, 403).
- **An admin who owns a personal tile** may personal-bind it into their own
  partition: PD-54's "admins never create them" is read as "never for
  someone else" — admin status adds nothing; the owner check is the rule.
- **v1 limits:** a plain provider (no `#instance`), a multi http slot, and
  not a provider already bound on the slot for everyone (409; the env and
  the meta also skip such a duplicate).
- **G1 vs PD-54.** 00 §3 G1 lists personal binds among the partition data
  no other principal gets, while 05 §3 and PD-54 let admins list (and
  delete) them. Followed 05/PD-54 (GET answers admins every row); flagged
  for the owner.
- **A removed requester's** rows stay (live:false, "… is gone") and aren't
  among `pathLeftovers`: a new tile at the same path that partitions would
  bring back a person's bind to a provider they still own. Low risk (the
  same person, their own tile); a later pack may drop them with the tile.
- **The shell's `<bx-bindings>` panel** isn't labelled (it lists pending
  slots for owners); the admin console's wiring view is.
- **The restart is synchronous** in the POST/DELETE handler
  (`StopPartition` waits for the processes, ≤ 5 s per generation).
- **An unreadable personal-binds record** makes every tile asked "holds
  data?" hold data (01 §2.2's lean), and is logged; the calls, env and
  meta of that person apply no personal bind.
- **Found in the shared scratchpad:** output of a `personal-binds` UI
  harness pass from an earlier F15 attempt (02:18, `h2-F15/out`); none of
  that attempt's code was on `pt/f15` (the branch sat at 982718a3), so this
  implementation is independent of it.
