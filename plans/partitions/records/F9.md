# F9 — records for the integrator

Work pack F9 (F5: attributed addressing of the own global instance;
plans/partitions/05 §6, 02 §4 rule 2's exception, 02 §6's attribution;
PD-16 decided, S3), branch `pt/f9` on `partitions` at 982718a3 (review
fixes on `pt/f9-fix`, §Review fixes). It fills
W1-wire's open F9 seams — `?xbin-partition=global` and
`Decision.Attribute` — and builds the proxy side of the client option and
SDK helper F8 shipped (`xbin.fetch(url, {partition: 'global'})`,
`xbin.GlobalURL(path)`), which it doesn't change. This pack edits neither
`docs/changelog.md` nor `plans/DECISIONS.md`; the two texts below go there.

## Changelog entry (docs/changelog.md, under the merge date)

- **Partitioned tiles: a person's partition can call its own tile's global
  instance** ([partitions.md](/docs/partitions.md) §The global instance and
  people's partitions, [protocol.md](/docs/protocol.md) §Authentication,
  §HTTP routes › Core, [auth.md](/docs/auth.md)). On a partitioned tile,
  `?xbin-partition=global` — what the client's `xbin.fetch(url,
  {partition: 'global'})` and the Go SDK's `xbin.GlobalURL(path)` add from a
  user partition — now reaches the tile's global instance instead of the
  caller's own partition, from the tile's frames, terminals, agent sessions
  and user-partition backends. xbind consumes the parameter (the backend
  never sees it, public ingress included) and the call arrives **as the
  partition's person**, whatever the credential:
  `X-XBin-User`, their live `X-XBin-User-Level`, `X-XBin-Role` `reader` for
  read or `writer` for write and terminal — never the self-call's `admin`,
  the partition's backend's calls included — `X-XBin-From` the tile, and
  `X-XBin-Partition: user:<id>` with its `X-XBin-Partition-Id`. A view-as
  frame reaches it as the viewed person, always as `reader` (with
  `X-XBin-Viewed-By`; writes refused). An admin calling the tile directly
  may use it too and keeps their own role; other people call a tile through
  its frame, as before. Refused: another tile, cron/bus/mail deliveries
  and path tickets (403), a value other than one `global` (400), and a
  tile without a global instance (`404 <tile> has no global instance`).
  Credentials already in `global` (the global instance, the owner token, a
  non-primary deployment) reach it as before. On every tile that isn't
  partitioned the parameter reaches the backend as any query parameter, as
  it always has. Nothing to change.

## Decision entry (plans/DECISIONS.md, the next free D-number)

- **D<next> — Partitioned tiles, F9: a user partition addresses its own
  global instance, as its person (2026-09-30).** Implements the same-tile
  path of PD-16 and S3 of plans/partitions/90-decisions.md; the design is
  plans/partitions/05-fabric-edges-global.md §6 and 02 §4 (rule 2's
  exception), §6. docs/partitions.md, docs/protocol.md, docs/auth.md.
  - **Chosen.**
    - **The proxy consumes, the broker decides.** The proxy
      (`internal/proxy/globaladdress.go`) takes `?xbin-partition` off the
      request only when the target's recorded mode has user partitions or
      can't be read (then F1's 409 gate holds it), and asks a second
      routing function, `Proxy.RouteGlobal` = `Broker.RouteGlobal`,
      installed by boot beside `Route`. Public ingress to a partitioned
      tile drops it too (`ingressQuery`; ingress reaches global anyway).
      Every other target is untouched: the parameter reaches its backend
      as before (10 §A.6, "consumed for partitioned targets only";
      TestNoPartitionGolden and TestZeroStateRoute unchanged). A separate
      function rather than a new `Route` argument keeps `Route`'s
      signature, boot's converter and every existing Route caller as they
      are.
    - **RouteGlobal = Route's deployment rules, then rule 2's exception**
      (`internal/broker/partitionglobal.go`, its own function, apart from
      routePartition's rule 4): deliveries (02 §5: no person drives them)
      and other tiles are refused before any rule runs; the deployment rules
      apply unchanged (a qualifier, write on a non-primary deployment,
      grants for people); a non-primary deployment and every credential
      without a person (the global instance, the owner token's frames and
      terminals, the root token) get routePartition's own answer — global
      already, a no-op; a person is taken from xbind state only — a user
      partition's instance token's registration, or the frame's, terminal's,
      agent session's or session's person (view-as: the viewed one) —
      checked live (PD-20: exists, enabled, reads the tile); then 404
      `util.ErrNoGlobalInstance` without `global`; else `Partition: global`,
      `CallerPartition: user:<id>` with its pkey, and for the tile's own
      credentials `Attribute{person, live level, role}`.
    - **The clamp:** `reader` for read, `writer` for write and terminal,
      never `admin` (S3's "never the self-call's admin"; terminal can
      already change the code, but admin at global reads as the tile itself
      to code such as the agent's `principal`). The level is read from the
      users store per call, so a level change or losing read applies to the
      next call.
    - **View-as is `reader`** at global, whatever the viewed person's
      level: the read-only gate refuses only non-GET methods, and a
      WebSocket upgrade is a GET.
    - **An admin calling directly keeps their own role** (rule 3) and gets
      no Attribute: identify already names them, and the clamp is about the
      tile's code acting for a person (S3's "never the self-call's admin"),
      not about people. Rule 4 grants a person nothing on `/api/<tile>/` by
      themselves (`grantedRole("", t)`), so every other person in person is
      refused with or without the parameter (`403 user:<id> is not granted
      access to <t>`), as today; their way in is the tile's frame.
    - **Path tickets** are marked on the request context by the server
      (`auth.WithPathTicket` in `servePathTicket`; `auth.ViaPathTicket`) —
      a ticket's principal is indistinguishable from its page's frame — and
      the proxy refuses them F5 (403) before RouteGlobal.
    - **Statuses:** `denyStatus` maps Route/RouteGlobal refusals — 404 for
      `util.ErrNoDeployment` and the new `util.ErrNoGlobalInstance`
      (`<tile> has no global instance`), 400 for a malformed parameter
      (any value but exactly one `global`, an empty one and a repeat
      included), 403 otherwise — the same order of gates as before.
    - **`global-address/1`** is `broker.GlobalAddressFeature`, a constant
      for the features list of `GET /api/xbin/partitions` (06 §6), which
      isn't mounted yet (F7b).
  - **Not chosen:** stripping the parameter on unpartitioned targets (a
    behaviour change for every existing tile, against compat rule 8 and the
    zero-state goldens); attributing (clamping) an admin's own direct calls
    (they hold admin on every tile, rule 3; clamped, the global instance's
    admin surface would answer only the owner token's credentials); opening F5 to readers
    in person (a new direct-call grant, wider than today's rule 4); a
    principal field for path tickets (a new field needs the tilesbx
    principal review and travels everywhere; the context marker reaches
    only the proxy); 404 before the person's liveness check (a person who
    can't read the tile learns nothing about it); passing the parameter
    through on ingress (a global instance would then see it from the
    public, against "the backend never sees it").

## Seams for the integrator

- **Filled here:** W1-wire's F9 row — `?xbin-partition=global` (the proxy)
  and `Decision.Attribute` (set by `Broker.RouteGlobal`, applied by F2's
  `identifyPartition`, unchanged).
- **Declared here, for F7b — guarded:** `broker.GlobalAddressFeature`
  (`"global-address/1"`) — list it in the `features` of `GET
  /api/xbin/partitions` when that route lands (06 §6). Nothing else reads
  it. `TestGlobalAddressFeatureServed` (internal/boot) asks a booted xbind
  for `GET /api/xbin/partitions?tile=…` as the owner: while it is a 404 it
  only logs; once the route is served, a `features` list without the word
  fails it (the W1-wire kind of open-seam guard).
- **For the F5 pack (cron and bus registrations in partitions):** a
  registration whose path carries `?xbin-partition` (any value) should be
  refused at `PUT` time — 400, saying `a <cron|bus> delivery acts in the
  partition it was registered for: ?xbin-partition=global is for <tile>'s
  own frames, terminals, agent sessions and backends` — rather than
  accepted and then refused (403 from `RouteGlobal`) at every fire. It
  fails closed today, so nothing leaks; the up-front refusal is a
  usability fix owned by the registration code (`util.QueryPartition`
  names the parameter).
- **New wiring:** `proxy.Proxy.RouteGlobal func(p auth.Principal, target
  *registry.Component, qualifier string) Decision`, installed in boot's
  `stepProxy` beside `Route` (`internal/boot/boot.go`, three lines);
  `auth.WithPathTicket(ctx)` / `auth.ViaPathTicket(ctx)` set by
  `internal/server/pathticket.go`'s `servePathTicket`.
- **For F10/F15 (routePartition):** RouteGlobal calls `routePartition`
  only for callers F5 leaves where they are (no person, non-primary, a
  deployment refusal); it never runs rule 4 (F5 is never cross-tile), so
  `partitionEdgeSeam`, `partitionConsentHolds` and `personalBindGrant` are
  never asked for an F5 call (TestRouteGlobal asserts the ledger counts
  nothing).
- **For B2a/B2b (the agent's shared conversations, PD-31):** an F5 call
  from the agent's frame or a user partition's backend reaches global with
  `X-XBin-From == self` and `X-XBin-User` set, so the template's existing
  `principal` (`access.go`) reads it as `whoUser`, never `whoSystem`.

## Deviations and open ends

- **The task's "(strip it otherwise)"** was read against 05 §6 and 10 §A.6
  ("consumed for partitioned targets only"): on unpartitioned targets the
  parameter is **not** stripped — the smallest safe option, since
  stripping would change what every existing tile's backend receives (a
  zero-state change). On partitioned targets it is always stripped, also
  when the call is then refused.
- **Terminal level clamps to `writer`**, not `admin` (above); 05 §6 says
  only "clamped to that level".
- **"No global: 404" comes after the caller checks**: other tiles,
  deliveries, path tickets and people who can't read the tile get their
  403 whatever the tile declares; only callers who could use F5 learn
  that there is no global instance.
- **Credentials already in `global` are honoured as a no-op** (05 §6
  lists them under neither "honoured" nor "refused"); without a global
  instance they get the 404 (the root token included, whose plain call is
  `403 sign in as a person`).
- **`global-address/1` isn't served yet**: its route is F7b's (wave 3).
  Until then a tile can't ask whether its xbind consumes the parameter;
  the client and SDK add it only in a user partition, which an xbind
  without F9 would still route to the person's own partition (the
  parameter passing to its backend).
- **Public ingress drops the parameter on partitioned tiles**
  (`ingressQuery`, internal/proxy/ingress.go) and decides nothing by it
  (ingress reaches global anyway); unpartitioned tiles' public requests
  are byte-for-byte as before.
- **`util.ErrNoGlobalInstance`, not `ErrNoPartition`**: 05 §6 names the
  404 `ErrNoPartition`, which exists as `runner.ErrNoPartition` (the
  runner's `no such partition`, wrapped, and answered 503 by boot's
  partition runner adapter). The broker refuses before any runner is
  asked, and the broker doesn't import the runner, so F9 adds the sentinel
  in util with 05's wire text `<tile> has no global instance` (05 §Wire).
  The same words also come from F2's `registeredPartition` as a **403**
  (a credential whose own partition is global — the global instance's
  token, a global cron — on a tile without one); protocol.md says the 404
  is F5's only. F2's text and status are left alone: wrapping `globalOf`
  would flip F2's documented 403s to 404.
- **The direct path is an admin's** (review finding 1): 05 §6's "a person
  who can read it" is, through Route's rule 4, only an admin (and the root
  token); an admin keeps `admin` there, unclamped — refuted above under
  *Not chosen*; docs say "an admin calling the tile directly".
- **No ui-harness pass**: the client's URL shapes are pinned by
  hack/xbin-client-partition.test.mjs (F8) and the SDK's by
  sdk/partition_test.go (F8); TestGlobalAddressWiring sends exactly those
  shapes to a booted xbind with a real backend. A Playwright pass from a
  partitioned tile's document (and a Go backend calling `GlobalURL` from a
  running user partition, which needs `--isolate`) is left to the F8
  finalization / I1.

## Review fixes (pt/f9-fix)

- **Medium — the direct path** (docs promised it to "a person calling the
  tile directly"; Route's rule 4 refuses every non-admin person first).
  Docs (protocol.md §Authentication and §HTTP routes › Core,
  partitions.md) and the changelog now say *an admin calling the tile
  directly*, keeping their own role; the admin-unclamped part is refuted
  (Decision entry, *Not chosen*: rule 3 already gives them admin on every
  tile, and clamping would leave the global instance's admin surface to
  the owner token's credentials alone). `TestRouteGlobal` and `TestGlobalAddressWiring`
  pin a reader (and a writer) in person → `403 user:<id> is not granted
  access to <tile>`.
- **Low — view-as:** `RouteGlobal` sets `reader` (Decision.Role and
  Attribute.Role) for any view-as credential, whatever the viewed
  person's level, so an F5 WebSocket (a GET) can't write as them. Pinned
  in the broker, proxy and boot tests (headers, `X-XBin-Viewed-By`, POST
  refused read-only).
- **Low — ingress:** public ingress to a partitioned tile now drops
  `?xbin-partition` (`ingressQuery`), so "the backend never sees it" holds
  there; protocol.md says so.
- **Low — ErrNoPartition vs ErrNoGlobalInstance, and the 403/404 text
  collision:** recorded under Deviations; protocol.md notes the 404 is

- **Low — `global-address/1`:** guarded by `TestGlobalAddressFeatureServed`

- **Low — tests:** a bus delivery through `DispatchBodyViaProxy`, the
