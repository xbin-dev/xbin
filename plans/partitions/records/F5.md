# F5 — records for the integrator

Work pack F5 (vault, registrations, notify, identity records) of the
partitioned-tiles plan, branch `pt/f5` on `partitions` at 982718a3, with
the review fixes on `pt/f5-fix` (§Review fixes at the end).
Implements the vault, registration and identity-record halves of **PD-20**,
**PD-21**, **PD-26**, **PD-27** and **PD-43** (plans/partitions/03 §C-§E,
06 §8) and fills W1-wire's F5 seams. This pack edits neither
docs/changelog.md nor plans/DECISIONS.md; the texts below go there at merge.

## Changelog entry (docs/changelog.md, under the merge date)

- **Partitioned tiles: each person's vault, cron jobs, bus subscriptions
  and notifications** ([partitions.md](/docs/partitions.md) §Vault and
  registrations, [resources.md](/docs/resources.md) §bus, §cron,
  [protocol.md](/docs/protocol.md) `/vault`, `/vaults`, `/cron/jobs`,
  `/bus/subscriptions`, `/notify`, `/iface-instances`, `/ingress-hosts`,
  `/ingress-routes`). On a partitioned tile a person's partition — its
  backend, and the person's terminals, agent sessions and frames on the
  tile — now uses the vault, cron and bus-subscription routes, which the
  API refused to it before: each reaches that partition's own store. Its
  vault values are readable by that partition's backend only; admins reach
  the global instance's vault, and `GET /vaults` counts how many people
  keep one (`partitions`), never their key names. Its cron jobs (at most 16,
  the 17th: 409; none more often than once a minute: 400) tick that
  partition while its person exists, is enabled and can read the tile, and
  resume by themselves; a tick whose start is deferred is retried with
  jitter before the next one is due. Its bus subscriptions (at most 16, the
  17th: 409) receive its own events on its scope's bus — which start it
  only when its own tile published them — and a shared bus's, or one
  another tile published for the person, only while it runs
  (`dormantDrops` counts the rest); the global instance's events never
  reach it. Subscribing to another partitioned tile's bus needs the person
  to be able to read that tile and, with the `partitionConsent` policy on,
  their consent (403; a subscription made before is `"dormant": true` and
  gets nothing meanwhile). While the tile is paused (its mode pending or
  invalid, or a switch deleting its data) its partitions' vaults and
  registrations can't change (409). Its interface instances and ingress hosts are
  stored for it and answered with `"dormant": true`, and never route; its
  ingress routes are none. Its backend's `POST /notify` reaches only its
  person (403 for anyone else). `?partition=` on a partitioned tile's
  vault, cron or bus-subscription route is refused (400) for everyone. A
  mode switch that deletes the tile's data deletes all of these too; they
  are deleted 30 days after the tile is removed or the person's id is
  given to someone new. Nothing changes for a tile without `"partition"`.
  Nothing to change.

## Decision entry (plans/DECISIONS.md, the next free D-number)

- **D&lt;next&gt; — Partitioned tiles, F5: people's partitions' vaults,
  registrations and records (2026-09-30).** Implements the vault,
  registration and record halves of PD-20, PD-21, PD-26, PD-27 and PD-43,
  and C5, S15, S19, C22 (plans/partitions/90-decisions.md; 03 §C-§E,
  06 §8). Design: plans/partitions/03-runner-data-vault.md §C-§E;
  docs/partitions.md §Vault and registrations.
  - **Chosen.**
    - **One directory per person's partition, beside the mode record.**
      `data/partitions/<TileKey>/<dep>/<pkey>/` holds `partition.json` (the
      identity record: tile, dep, user, uid, created, lastStarted, state
      active|orphaned, reason, rebuilt) and the registration files
      `cron.json`, `bus-subscriptions.json`, `iface-instances.json`,
      `ingress-hosts.json` — schema 1, the deployment files' rows, plus the
      tile and the partition the file belongs to, which every load checks.
      The vault is `data/vault/.partitions/<TileKey>/<dep>/<pkey>.json`
      (the global envelope plus tile, deployment and partition; 0600;
      barrier-sealed; never bound into a sandbox). The record is written
      before anything else of the partition lands (its first registration,
      vault key or start — `PartitionEnv`, once per spawn, stamps
      `lastStarted`), so a TileKey directory always names its tile for the
      boot load. An older xbind never reads any of it, so it never fires a
      person's job as the tile's; a backup of the tile carries global's
      rows only (they never join today's maps: S15).
    - **Which store a call reaches: the principal the partition gate
      stamped.** A credential of the tile acting in a person's partition
      (`auth.Principal.Partition`, the gate's stamp; an instance token's
      own) reaches that partition's vault and registrations, always on the
      primary; everyone else — admins, other tiles, the root token —
      today's (global's). `?partition=` on a partitioned tile's vault, cron
      and bus-subscription routes is 400 for everyone (the tile's recorded
      mode has user partitions, or can't be read), ignored elsewhere (C22).
    - **The liveness gate (PD-20) is asked at every tick, publish and
      delivery, never cached**: the tile runs people's partitions (not
      paused), is enabled, the deployment is the primary, and the person
      exists, is enabled, can read the tile and has the directory's pkey
      now (the same uid). A person who regains access resumes without
      registering again; a recreated id (a new uid, a new pkey) never fires
      the old incarnation's jobs.
    - **Deliveries carry the partition** — `Principal{Component: xbin/cron
      | xbin/bus, Partition: <the registration's>}` (F2's delivery
      principals), which Route sends to that partition as a background
      start (F3). A cron tick the runner defers (503 `partition start
      deferred`) is retried with jitter (10–30 s, less near the next tick)
      until the next tick is due; one still deferred is missed and counted
      (`MissedTicks`). Caps (C5): 16 jobs, 16 subscriptions a partition,
      no schedule more often than once a minute.
    - **The bus.** `busSubs.publishStamped` takes the event's stamp and the
      tile whose credential published it: global's reaches today's
      subscriptions only; a person's (publishPartitionPushSeam) that
      person's partition's, and may start it only when the publisher is the
      subscriber's own tile (its backend, frames, terminals — the partition
      runs its own code, 03 §D); an unstamped event (a shared bus, an
      unpartitioned scope's) today's and every matching partition
      subscription. A delivery that may not start its partition is queued
      only while it runs (`partitionRunning`, the runner's side) — a
      skipped one counts as `dormantDrops`. Only partition mail (F6)
      cold-starts a partition from outside it.
    - **A subscription to a partitioned scope's bus is a reach of that
      scope by the partition (05 §1-§2, PD-13)**: `partSubReach` asks
      `addressedPartition` for the partition's instance — on another tile's
      scope, its person must read that scope's tile and, with
      `partitionConsent` on, have consented (`partitionConsentHolds`, F10's).
      Asked at registration (403), at every publish and at every delivery
      (skipped: `dormantEvents`, the reason in `lastError`), never cached;
      the row lists `dormant` meanwhile. The registration and each
      delivery count one edge in the partition's egress ledger
      (`reachPartition` → `partitionEdgeSeam`), as the data plane's reach
      does.
    - **Dormant registrations (PD-21)**: the partition gate's
      GlobalOnlyDormant arm passes, stamped; `routeTarget` answers a
      person's partition's own target, always dormant, and the stores write
      its files (a NUL-joined target in routeTarget's deployment string, so
      `netfn.go`/`ingressfn.go` stay untouched); `routesHidden` answers a
      partition's terminator no routes.
    - **Notify (PD-27)**: `notifier` gives a user partition's instance
      token its person as `self` — the frame's rule; the global instance
      keeps the backend's.
    - **Identity records (PD-43, PD-26)**: `partitionAdoptUID` now adopts
      the one uid a person's live `ns.json` **and** `partition.json` records
      agree on, made after the second their users-store record was — one
      rule, `adoptablePartitionUID`, which reads both; conflicting uids
      adopt none. Boot's load of the registrations re-adopts at once for a
      person whose uid an older xbind's rewrite of the users store dropped
      (`readoptPartitionUID`: adopts or does nothing, never mints), so
      their jobs fire without waiting for their next request.
      `partition.json` keeps the crash metadata admins see (PD-24):
      `lastExit`, `restarts` (exits the runner's crash watch saw, since the
      record was made) and `crashLoop` (cleared by a start), written
      through the runner's new `PartitionExit` hook, so they survive a
      restart of xbind. The namespaces'
      sweep also sweeps records: a missing `partition.json` is rebuilt from
      `ns.json`; the orphaning events are the namespaces' (the users-store
      delete hook through `PartitionUserDeleted`, an id held by someone new,
      the tile gone — reclaimed when it returns); an orphan is deleted
      30 days later (`partitionRetention`) with its registrations and vault,
      never while its tile is paused. A new tile at a removed tile's path
      drops the path's partitions' registrations (D85, as
      `dropDormantAt` does the deployments'); their records and vaults are
      leftovers of the path (`partitionLeftovers`).
    - **Holds data and the switch's wipe** (01 §2.2, §2.6): three stores,
      each with the wipe hook of its name — `partition-vault`,
      `partition-registrations`, `partition-records` — deleting every
      person's on `wipeEverything` (the broker's rows dropped first), none
      on `wipeGlobal`/`wipeNone` (H1); the dry run counts vault keys,
      registrations and people. The mode record stays (the switch writes
      it next). The wipes and drops hold the stores' file locks (cron's,
      the bus's, the dormant files', the vaults', the records'), and every
      write of a person's registrations or vault is refused (409) under
      that same lock while the tile is paused — the switch's hold included
      — so nothing written during a switch brings a partition back.
      "Holds data" counts vault files, never the empty levels a removal
      leaves (and removals take those levels too). A vault written in
      plain under `--insecure-vault` is sealed when the barrier is first
      initialized, as the global ones are (`migratePartitionVaults`).
  - **Not chosen:** partition rows in today's `data/cron-jobs.json` /
    `bus-subscriptions.json` with an owner field (an older xbind would fire
    them as the tile's; backups would carry them); a `?partition=` for
    admins (PD-07: an admin never reaches a person's vault or
    registrations); cold-starting a partition for a shared bus's events
    (every shared publish would start every subscriber's partition);
    storing `dormant` in `partition.json` (liveness is asked at every use,
    PD-20); changing `routeTarget`'s signature (netfn.go is F15's file this
    wave).

## Deviations and open ends

- **`partition.json`'s `state` is `active|orphaned`, never `dormant`**
  (03 §E lists `active|dormant|orphaned`): dormancy is the liveness gate's
  answer at every use (PD-20), which a stored state would contradict the
  moment a person regains access. `lastExit`, `restarts` and `crashLoop`
  are stored (the review fix); `restarts` counts every unrequested exit
  since the record was made, `crashLoop` is cleared by the next start.
  The owner may want 03 §E amended to match.
- **Dormant registrations are written through `routeTarget`'s string**
  (`dep NUL pkey NUL part NUL user NUL uid`), decoded by `storeInstances`
  / `storeIngressHosts` (dormantroutes.go), rather than a new return value:
  `netfn.go` is F15's this wave. A cleaner `routeTarget` returning a
  target struct can replace it when netfn.go is free.
- **The protected primary's vault rule applies to partitions too**: a
  person's terminal can't write their own partition's vault on a tile
  whose primary is protected (its backend can). Smallest change; the rule
  keeps "no terminal writes a protected primary's secrets".
- **A person's partition subscribing to another partitioned scope's bus**
  needs the tile's grant (today's) **and** the partition's reach of that
  scope (`partSubReach`, addressedPartition's answer: person-read, and
  consent under the policy), at registration, publish and delivery. A
  refusal at registration answers 403 even when the target's mode record
  can't be read (the data plane answers 409 there); the text says why.
- **Paused tiles refuse a person's registration and vault writes (409)**,
  deletes included — the global instance's registrations keep today's
  behavior (stored, dormant). The residual window is F13a's: its switch
  releases the hold (`end()`) just before the rescan settles the new mode,
  so a tile that was running (a switch after "keep") accepts writes for
  that instant; a pending tile stays held until the rescan.
- **Subkeys**: the records' sweep doesn't erase `part:` backup subkeys;
  F4's namespace sweep does for partitions with namespaces, and a
  partition without namespaces has no archives until F17b.
- **An admin's own frame** on a partitioned tile lists its own partition's
  cron jobs and subscriptions (it acts in the admin's partition, PD-11);
  before, an admin's frame listed everything. Admins' own sessions still
  list global's.
- **Retries after `Close`**: a deferred tick's retry timer may fire once
  after the broker closes (it re-checks the job is still scheduled; the
  scheduler is stopped, so no new ticks).

## Review fixes (pt/f5-fix)

- **High — cross-tile bus subscriptions skipped the reach rule.** A
  person's partition subscribing to another partitioned tile's bus was
  checked by the tile's grant only, so carol (no read on apps/pg) and alice
  (no consent, `partitionConsent` on) got apps/pg's events. Now
  `partSubReach` (partitionbussubs.go) runs addressedPartition for the
  partition's instance at registration (403), every publish and every
  delivery (skipped, `dormantEvents`, `lastError`), and the list shows the
  row dormant; F10's `partitionConsentHolds` applies there with no change.
- **Medium — cold starts by other tiles.** `cold` is now "the publisher's
  tile is the subscriber" (`publishPartitioned` passes the principal;
  `publisherTile` resolves window sub-paths), so another tile's code acting
  for a person never starts that person's partition in the background.
- **Medium — test gaps**: the tests above (cross-tile read/consent/cold,
  lost read, tile-removed reclaim, the paused retention, the deferred tick
  through the real proxy, which pins the 503's wording end to end).
- **Low:** "holds data" counts vault files only, and removals take the
  empty levels (`removeEmptyDirs`); plain partition vaults are sealed at
  the barrier's init (`migratePartitionVaults`); boot re-adopts a dropped
  uid (`readoptPartitionUID`); the wipe and drop paths hold the file locks
  and writes are refused while paused (`dropPartitionRegistrationsAt`
  already ran under `dropDormantAt`'s cron/bus file locks — it now takes
  the dormant files' lock too); `setPart` keeps unchanged jobs' entries,
  missed counts and pending retries; failed partition ticks and
  deliveries log the status only (PD-46); `lastExit`/`restarts`/`crashLoop`
  persisted (runner `PartitionExit` hook); 95's contention table lists
  `partitionclass.go`, and the tests no longer use `GET /logs` as the
  unconverted example; protocol.md, partitions.md and resources.md give
  the 17th registration's 409, the paused 409 and the cross-tile rule;
  `adoptablePartitionUID` is the one adoption rule.
