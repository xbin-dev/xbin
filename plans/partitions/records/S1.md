# S1 — records for the integrator (the partitions smoke)

**Which "S1" this is.** The orchestrator ran this as work pack "S1" of
wave 2. plans/partitions/95-work-packs.md defines no pack of that name: this
is an early slice of its **I1** (Integration) — an end-to-end smoke of
partitioned tiles as built through wave 1 (spec 00 §3's guarantees, 02's and
03's tests, 01 §2.3-§2.6). It is **not** isolation finding S1 of
90-decisions §G (the cross-tile edge PD-13 decides), although its
cross-tile case probes that edge. The decision entry below calls it "the I1
smoke slice". Branch `pt/s1`; the review's fixes are on `pt/s1-fix`
(§Review fixes).

What it adds:
- `test/isolated/partitions_smoke_test.go` (the cases) and
  `test/isolated/partitions_smoke_fx_test.go` (the fixture). They drive a
  real `xbind --isolate` with owner auth on.
- One fix in merged code (F13a's switch, below), with a CI unit test,
  `internal/broker/partitionswitch_remount_test.go`.

**The smoke runs on a dev box only.** test/isolated needs user namespaces,
a base rootfs and gocryptfs. CI builds no rootfs, so `make integration`
compiles the smoke there but `xbindtest.Require` skips it. What CI does run
is the fix's regression test, `TestPartitionSwitchRemountsMain`, which uses
nsFakeVolumes' stand-in gocryptfs.

This pack edits neither docs/changelog.md nor plans/DECISIONS.md. The two
entries below go there in the merge that brings this branch in.

## Changelog entry (docs/changelog.md, under the merge date)

The fix below corrects F13a's switch before any release carries it, so
nothing here is builder-visible on its own. If F13a's entry is already
folded, fold this sentence into it; otherwise drop it:

- A partition mode switch that deletes the tile's own data (between user
  partitions and unpartitioned, or removing `"global"`) leaves the tile
  running on its new, empty data at once, even when the switch stopped
  part-way. Before, it answered 502 "… is held: it uses the encrypted
  resource …, and its decrypted view isn't mounted" until xbind restarted
  or the workspace next changed.

## Decision entry (plans/DECISIONS.md, the next free D-number)

- **D&lt;next&gt; — Partitioned tiles, the I1 smoke slice (run as "S1"): an
  end-to-end smoke on a real isolated xbind; a switch mounts the tile's own
  volumes again (2026-09-30).**
  - **What it smokes:**
    - 00 §3's guarantees G1 (no route hands one person's partition data to
      another) and G2 (an admin reaches their own partition, never a
      person's; PD-08 view-as).
    - 02 §2-§4 and §10: routing, rule 2 (self-calls), rule 4 (a
      partitioned tile's call to another reaches the same person's
      partition, PD-13), the identify headers, `XBIN_PARTITION`, the
      document meta, and instance tokens bound to their generation and the
      person's uid.
    - 03 §A.4-§A.6: per-partition logs, PD-18 caps, the idle stop.
    - 03 §B: namespaces, `shared`, `"read"`, PD-17 (people's partitions on
      the primary only) and §B.9 (no seeding between partitions).
    - 03 §E: a person deleted and created again gets a new uid and a fresh
      partition.
    - 05 §5: ingress and other tiles reach global.
    - 01 §2.3-§2.6: auto, pending, keep, switch, the wipe.
  - **Tests:** `test/isolated/partitions_smoke_test.go` (dev box only: it
    skips in CI, which has no rootfs) and
    `internal/broker/partitionswitch_remount_test.go` (CI).
  - **Chosen.**
    - **One fixture: four tiles, five people.** Every tile runs one Go
      probe over the SDK.
      - The probe echoes `XBIN_PARTITION`, `xbin.Partition()`,
        `xbin.PartitionUser()`, `xbin.Caller(r)`, its instance token and a
        boot id per process.
      - It reads, writes and lists a per-partition kv (`kv`), a shared kv
        (`board`, `"shared": true`), a per-partition filesystem (`files`)
        and a read-shared filesystem (`pub`, `"shared": "read"`).
      - It logs each value it stores, returns its sandbox's
        `/proc/self/mountinfo`, and relays a call through `xbin.Client`.
      - The tiles: `apps/pt` (`["user", "global"]`, with a
        `partitionNote`); `apps/pt2` (`["user"]`, granted writer on
        `apps/pt`); `apps/pcall` (unpartitioned, granted writer on
        `apps/pt`); `apps/plain` (unpartitioned, holds data, later asks to
        partition).
      - The people: alice, bob and dave are users who read `apps/*`; carol
        and erin are workspace admins; the owner token is the fifth
        credential.
    - **Data is named after whoever stored it.** alice stores
      `alice-secret`, `alice-note`, and a key and a file named `alice-only`;
      global stores `global-only`. So any leak shows by name, and each
      listing is checked for its exact contents.
    - **Every attempt has an exact answer.** A route that reaches a person
      returns that person's own value, and never global's. A route that
      reaches global returns global's value. A refusal must have its status
      and its reason. The only enumerated answers are the
      `?xbin-partition=` rows, which accept today's answer or F9's (see the
      notes).
    - **People reach a tile's API through its frame**, as a browser does. A
      user's own session is no API principal of a tile unless they are an
      admin.
    - **The fix: a switch mounts main's volumes again, on every way out.**
      F13a's switch wipes main's namespace (user ↔ unpartitioned, or
      removing `"global"`), which unmounts and removes the tile's volumes at
      today's keys. Only `MountEncrypted` mounts main's volumes (at
      provision, unseal, a `cap:containers` change, a restore). So the
      instance at today's keys stayed held until xbind restarted or the
      workspace next changed. That instance is the unpartitioned one, or
      global; a person's shared volumes live there too.
      - `runSwitch` now defers `MountEncrypted` right before the wipe hooks
        run, when the switch owns main's data and deletes some of it.
      - So a wipe that stops part-way (500) and a decision that isn't
        recorded (409) remount too, still under the namespace holds.
    - **The idle stop runs only on request** (`XBIN_SMOKE_REAP=1`,
      `TestPartitionsSmokeReap`). `partitionIdleReap` is a 10-minute
      constant with no knob, and a knob would be new daemon surface for a
      test, so the case waits it out (≈ 11 min).
  - **Not chosen:**
    - An env knob for the idle stop: new surface, and the runner's unit
      test already drives the clock.
    - Running under `test/` without isolation: people's partitions answer
      503 there (PD-19).
    - Building a rootfs in CI to run the smoke there: the CI budget. The
      unit test carries the fix instead.

## Bugs found (in merged code)

- **Fixed — a switch left the tile held (F13a/F4).**
  - **Repro:** a tile `["user", "global"]` holds data in a filesystem
    resource. Change the manifest to no `partition`, then `POST
    /partitions/mode {act: "switch", …, confirm: <tile>}` → 200. Any call to
    the tile then answers 502 `component <tile> is held: it uses the
    encrypted resource res:<tile>/files, and its decrypted view isn't
    mounted`. This lasts until xbind restarts or the workspace next changes
    (the watch loop's provision calls `MountEncrypted`, boot/serve.go).
  - **Cause:** the wipe unmounts and removes main's volumes, and nothing
    mounts them again.
  - **Fix:** `runSwitch` defers `MountEncrypted()` before its wipe hooks
    run, when `OwnsMain` and the kind deletes something
    (internal/broker/partitionswitch.go). Every exit remounts, including a
    wipe that stops part-way and a decision that can't be recorded.
  - **Tests:**
    - CI: `TestPartitionSwitchRemountsMain` covers unpartitioned → user +
      global, removing global, and a wipe hook that fails part-way. It
      fails with the remount removed.
    - Dev box: the smoke's mode-switch case fails without the fix, after
      4 min, on that 502.

## Deviations and notes

- **"Another tile bound to it"** means a tile granted on the partitioned
  one (`uses` plus a grant), because typed binds (F15) aren't built. Its
  backend and its frames reach global.
- **The ingress binding comes before any instance starts.** `POST
  /bindings` restarts every live instance of the tile, people's included
  (expected: the network changes). A binding made mid-test raced the boot
  comparisons.
- **The fixture keeps its `partitionNote` when it asks to be
  unpartitioned.** The switch page shows the current manifest's note, which
  is the new code's, so a tile that drops both `partition` and its note
  shows no note. Builders should keep the note in the code that asks for
  the switch; /docs/partitions.md may want to say so.
- **View-as and `GET /frame-token`.** 02 §10 says "a view-as viewer gets
  the document with … no frame token". The document has none, but the
  renewal route still mints one for a view-as session (02 §10 keeps renewal
  as it is). That token carries the impersonator, and every partition route
  refuses it with the PD-08 message, so nothing leaks. F14/F11 may want the
  route to refuse it outright.
- **Re-enabling a person revives their partition's instance token.** While
  the person is disabled the token is 401. Once they are enabled again the
  same token authenticates (02 §2's coverage rule: enabled and reading the
  tile), because disabling doesn't stop the instance. `StopPartitionsOf` and
  `RevokeUserPartitionInstances` are F7b's seams.
- **Deleting a person leaves their old instance running** (F7b's
  `StopPartitionsOf` and `PartitionUserDeleted`). Its data stays on disk
  under the old partition id. Its token is 401 at once, because coverage
  checks the uid, and a person recreated under the same id never adopts the
  old uid: their partition records predate the new user record
  (`adoptablePartitionUID`, PD-43).
- **Not yet built, so these pass through** (not failures): F9's
  `?xbin-partition=` (above).
- **`/api/<tile>+main/…` on a tile without deployment records** answers
  404 `no such component` (D119c: main alone, today's URLs). Once `dev`
  exists, it names the primary, and bob's frame reaches his own partition
  there.
- **Out of scope** (later packs; I1's list):
  - F5: bus subscriptions, cron, vault and notify.
  - F7a: terminals.
  - F7b: `GET /partitions`, a partition's own log route and `GET
    /tile-status` for a partition credential (both unconverted rows today:
    refused, as the logs case checks for `/logs`), and the `partitions`
    event and partition-scoped events on `/ws/events`.
  - F9 and F10 (consent is off by default, so the cross-tile case runs
    without it).
  - F15.
