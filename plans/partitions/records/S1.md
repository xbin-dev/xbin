## Decision entry (plans/DECISIONS.md, the next free D-number)

- **D&lt;next&gt; — Partitioned tiles, S1: an end-to-end smoke on a real
  isolated xbind; a switch mounts the tile's own volumes again
  (2026-09-30).** Smokes 00 §3's guarantees G1 (no route hands one person's
  partition data to another) and G2 (an admin reaches their own partition,
  never a person's; PD-08 view-as), 02 §2-§3 and §10 (routing, identify
  headers, `XBIN_PARTITION`, the document meta, instance tokens), 03 §A.5
  (PD-18 caps), §A.6 (the idle stop), §B (namespaces, `shared`, `"read"`,
  PD-17 — people's partitions on the primary only, §B.9 no seeding between
  partitions), 05 §5 (ingress and other tiles reach global) and 01
  §2.3-§2.6 (auto, pending, keep, switch, the wipe). Test:
  `test/isolated/partitions_smoke_test.go`.
  - **Chosen.**
    - **One fixture, three tiles, four people.** `apps/pt` (`"partition":
      ["user", "global"]`, a `partitionNote`), `apps/pcall` (unpartitioned,
      granted writer on `apps/pt`) and `apps/plain` (unpartitioned, holds
      data, later asks to partition) all run one Go probe over the SDK that
      echoes `XBIN_PARTITION`, `xbin.Partition()`, `xbin.PartitionUser()`,
      `xbin.Caller(r)`, its instance token and a per-process boot id, and
      reads and writes a per-partition kv (`kv`), a shared kv (`board`,
      `"shared": true`), a per-partition filesystem (`files`) and a
      read-shared filesystem (`pub`, `"shared": "read"`). People: alice,
      bob and dave (users reading `apps/*`), carol (a workspace admin), and
      the owner token.
    - **People reach a tile's API through its frame** (a user's own session
      is no API principal of a tile unless they are an admin), as a browser
      does.
    - **The fix: a switch mounts main's volumes again.** F13a's switch wipes
      main's namespace (user ↔ unpartitioned, or removing `"global"`) and
      unmounts and removes the tile's volumes at today's keys, but only
      `MountEncrypted` mounts main's volumes (at provision, unseal, a
      `cap:containers` change, a restore), so the instance at today's keys
      — the unpartitioned one after a switch to unpartitioned, or global —
      stayed held until xbind restarted. `actSwitch` now calls
      `MountEncrypted` after the wipe when it owns main's data (as a backup
      restore that replaced main's data does). Commit `fix(S1): …`.
    - **The idle stop runs only on request** (`XBIN_SMOKE_REAP=1`,
      `TestPartitionsSmokeReap`): `partitionIdleReap` is a 10-minute
      constant with no knob, and a knob would be new daemon surface for a
      test; the case waits it out (≈ 11 min).
  - **Not chosen:** an env knob for the idle stop (new surface, and the
    runner's unit test already drives the clock); `test/` without isolation
    (people's partitions answer 503 there — PD-19).

## Bugs found (in merged code)

- **Fixed — a switch left the tile held (F13a/F4).** Repro: a tile
  `["user", "global"]` holding data in a filesystem resource; change the
  manifest to no `partition`; `POST /partitions/mode {act: "switch", …,
  confirm: <tile>}` → 200; then any call to the tile answers 502
  `component <tile> is held: it uses the encrypted resource res:<tile>/files,
  and its decrypted view isn't mounted (xbind's log says why)` until xbind
  restarts. Cause: the wipe unmounts and removes main's volumes, and
  nothing mounts them again. Fix: `actSwitch` calls `MountEncrypted()`
  after the wipe (internal/broker/partitionswitch.go). The smoke's
  mode-switch case fails without it (verified by reverting the fix).

## Deviations and notes

- **"Another tile bound to it"** is a tile granted on the partitioned one
  (`uses` + a grant): typed binds (F15) aren't built; its backend and its
  frames reach global.
- **The ingress binding comes before any instance starts.** `POST
  /bindings` restarts every live instance of the tile, people's included
  (expected: the network changes); bound mid-test, the restart raced the
  boot comparisons.
- **The fixture keeps its `partitionNote` when it asks to be
  unpartitioned**: the switch page shows the current manifest's note (the
  new code's), so a tile that drops `partition` and its note shows none.
  Builders should keep the note in the code that asks for the switch;
  /docs/partitions.md may want to say so.
- **View-as and `GET /frame-token`.** 02 §10: "a view-as viewer gets the
  document with … no frame token". The document has none, but the
  renewal route still mints one for a view-as session (02 §10 keeps
  renewal as is). The token carries the impersonator, and every partition
  route refuses it (403 `… keeps alice's data private: view-as can't open
  it`), so nothing leaks; F14/F11 may want the route to refuse it outright.
- **Re-enabling a person revives their partition's instance token.** While
  disabled it is 401; once enabled again the same token authenticates (02
  §2's coverage rule: enabled and reading the tile), because disabling
  doesn't stop the instance — `StopPartitionsOf` /
  `RevokeUserPartitionInstances` are F7b's seams.
- **Not yet built, so passed through** (not failures): `?xbin-partition=`
  reaches the backend as a plain query (F9); bob's `?xbin-partition=global`
  lands in his own partition.
- **`/api/<tile>+main/…` on a tile without deployment records** answers 404
  `no such component` (D119c: main alone, today's URLs); once `dev` exists
  it names the primary and bob's frame reaches his own partition there.
- **Out of scope** (later packs): F5 bus subscriptions, cron, vault and
  notify; F7a terminals; F9; F10; F15.
