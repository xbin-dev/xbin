# F4 — records for the integrator

Work pack F4 (data namespaces and volumes) of the partitioned-tiles plan,
branch `pt/f4`. Implements **PD-48** in full and the data side of PD-01,
PD-04, PD-05, PD-13 (the reach checks), PD-26 (the orphan rules for
namespaces), PD-43 (the namespace records and the adoption helper) and
PD-45; the design is plans/partitions/03 §B (with 04 §1-§2 and 05 §2).
This pack edits neither docs/changelog.md nor plans/DECISIONS.md; the texts
below go there at merge.

## Changelog entry (docs/changelog.md, under the merge date)

- **Partitioned tiles: each person's data** ([resources.md](/docs/resources.md)
  §Partitioned tiles, [partitions.md](/docs/partitions.md) §Shared resources,
  [protocol.md](/docs/protocol.md) kv/blob/bus and `/runtime`). In a
  partitioned tile's scope every resource that isn't `"shared"` is kept per
  person: each person's partition has its own kv file and volumes under
  `data/resources-enc/.partitions/`, reached at the same `XBIN_RES_*` paths
  and `res:` ids, while the global instance and every shared resource keep
  today's keys. A `"shared": "read"` resource is mounted read-only in
  people's partitions and their kv, blob and bus writes answer 403
  `res:<scope>/<name> is read-only for people's partitions`. A person's
  partition of another partitioned tile holding a grant reaches the same
  person's data only if they can read the tile (and, with the
  `partitionConsent` policy on, allowed it); other tiles reach the global
  instance's. Each partition has its own disk ceiling (507 for that person
  only), is unmounted after an hour unused, and is deleted 30 days after
  its person is deleted or its tile removed. A paused partitioned tile's
  data answers 409. `/runtime`'s resource rows gain `partition` on
  people's partitions' rows. Nothing changes for a tile without
  `"partition"`. Nothing to change.

## Decision entry (plans/DECISIONS.md, the next free D-number)

- **D&lt;next&gt; — Partitioned tiles, F4: people's data namespaces,
  shared resources and volumes (2026-09-29).** Implements PD-48, and the
  data side of PD-01, PD-04, PD-05, PD-13, PD-26, PD-43 and PD-45
  (plans/partitions/90-decisions.md; 03 §B, 04 §1-§2, 05 §2).
  - **Chosen.**
    - **One key function, one more level.** `nsKeysFor(scope, dep, pkey)`
      and `resKeysIn(rt, dep, pkey)` (deploydata.go) answer today's keys
      byte for byte for `pkey == ""` (`scopeKeys`/`resKeys` are now their
      wrappers); a person's namespace is
      `.partitions/<escS>/<dep>/<pkey>`, `dep` spelled for main, with its
      own `kv.db`, bucket labels (`kv:<NS>/<bucket>`) and volumes
      (`<NS>/fs/<name>`). The pkey is `u-` + 32 hex, checked on every use
      (`pkeyOK`); the workspace scope is never partitioned.
      `TestNoAdHocResourceKeys` now also refuses a `.partitions` literal or
      `partitionsLevel` joined with `+` anywhere in the broker but
      deploydata.go.
    - **One decision for which namespace** (`partitionReach`, from
      `reachRes`, and `PartitionEnv`): a resource of a scope whose root's
      recorded mode has user partitions is the caller's partition's unless
      shared; global and shared at today's keys; `"read"` sets `readOnly`,
      which `readClamp` turns into the 403 for every write (kv, blob, bus).
      A cross-scope caller acting in `user:<id>` reaches `<id>`'s namespace
      only with `<id>`'s read access on the target tile and — with
      `Broker.Policies().PartitionConsent` — their consent (a seam until
      F10); any other tile reaches today's (global's). A paused root
      (pending, invalid) or an unreadable mode record answers 409: never a
      fall-back to today's keys (F1's open end). Cron resources aren't
      partitioned here (their jobs are the registrant's, F5). User
      partitions reach data on the primary only (PD-17).
    - **Whose a namespace is**: `ns.json` gains `partition: {user, uid,
      tile, created, orphan?}`, written before anything lands (a writer's
      first kv/blob request, or the instance's first start), so the orphan
      rules and uid adoption never guess.
    - **"Holds data" counts any entry under `.partitions/<escS>`** of the
      scope the tile roots (store `partition-namespaces`): a partition
      exists once written or started, and the rule leans toward asking. A
      tile without resources never gets one.
    - **Orphans only on a recorded event** (PD-26): the users store's delete
      hook (`PartitionUserDeleted(user, uid)`), a record older than the id's
      current holder (or naming another uid than the store's), or the tile
      gone from the registry (reclaimed if it returns). Swept 30 days later
      (`partitionRetention`), never while the tile is paused; the sweep
      erases the partition's `part:<TileKey>/<dep>/<pkey>` backup subkey
      under the tile's backup lock. A missing record, an unknown person and
      a mode change never orphan.
    - **The switch's wipe** (`wipePartitionNamespaces(tile)`): every
      partition namespace of the scope, each under its hold, volumes
      unmounted and verified first, kv files closed; an error keeps the
      switch from completing.
    - **Binds**: a user partition's remap binds its own volumes at the
      canonical paths; a shared resource's `ResBind{Shared: true}` binds
      main's data only at its own canonical path and only where the runner
      re-derives "shared" from the registry (`Registry.PartitionedScope` +
      `Resource.Shared`, `sharedResources`), never on the broker's word
      (C7); a `"read"` resource is bound read-only whatever the entry says.
      `mainData` treats `.partitions` as not main's.
    - **Volumes (PD-48)**: resenc locks per `(dirKey, name)` (an epoch
      keeps a seal's `UnmountAll` authoritative over Ensures in flight); new
      partition volumes are initialized with `-scryptn 10`; `Hold`/
      `UnmountIdle` unmount a partition's volume nobody held for 60 min and
      whose instance the runner doesn't report running; the partition's kv
      file closes on the same rule. The disk monitor's scan runs the reaper.
    - **Disk (03 §B.7)**: each partition namespace is its own quota bucket
      (its ceiling the tile namespace's limit, lowerable by the partitions
      API), its own candidate on low disk, alerts to admins only (tile and
      partition key, never contents), never counted in the tile-visible
      "N tile(s) over quota" line. `/runtime` lists per-partition rows.
  - **Not chosen:** reusing the deployments' sweep for partitions (its
    claimant rule would orphan every partition); orphaning on a pending,
    declined or invalid mode, a missing index or an unknown user (03 §B.8);
    trusting `ResBind.Shared` without the registry; unmounting idle volumes
    before the runner can say which instances run (the default keeps
    today's "mounted until seal").

## Deviations and open ends

- **`ResBind.Shared`** is a new field in `internal/runner/deploy.go` (F3's
  file): one line, beside `RO` (whose comment no longer says "v1 never
  sets it").
- **Moved code, to keep files under the 800-line cap:** `kvStore`/`openKV`
  from resources.go to deploydata.go's kv section, and
  `writeNamespaceRefusal` to partitionreach.go (it now also answers a
  partition refusal's status). nsAvailable/nsWriting/nsStartBlocked are
  thin wrappers over `nsAvailableID`/`nsWritingID`/`nsStartBlockedID`
  (nsenter.go, deployns.go) so a partition's `nsID` (which gains `pkey`)
  takes the same holds and gates.
- **ns.json's identity is nested** (`"partition": {user, uid, tile,
  created, orphan}`) rather than flat; `dep` is the existing
  `deployment`. The orphan event lives there; `orphaned` keeps the time.
- **`tile-removed` is recorded by the sweep** when the scope root is no
  longer a registered tile — xbind has no removal flow to hook — and
  cleared if the tile comes back within the retention. The mode record's
  removal after the sweep (06 §10) is left to F13a/F7b.
- **Paused scopes answer 409** on the kv/blob/bus routes (not only the
  proxy): with R = user and the tile paused, the identity plane answers no
  partition, and falling back to today's keys would hand global's data
  out.
- **The cross-scope read and consent checks are in F4's reach** (the plan
  lists them under F10 too); F10 fills only the consent record and ledger
  seams. Route rule 4 (calls) stays F2/F10's.
- **A workspace-level filesystem/sqlite edge is not bound in a user
  partition** (`Omit`, the path absent), as for non-primary deployments;
  shared resources of a primary beyond main bind from that deployment's
  volume (RO for `"read"`, which the runner enforces too).
- **A person's own partitioned bus refuses publishes (503)** until F2/F5
  fill `publishPartitionBusSeam`; a shared bus works as today.
- **Partition retention is 30 days** (PD-26); deployments keep their 14.
- **Not done here:** `nsVolume`/`MountEncrypted`'s remount loop doesn't
  visit partition mounts (a partitioned scope can't hold `cap:containers`,
  so their single-tenant mode never changes); `OrphanedNamespaces` (the
  deployments' admin list) doesn't list partition orphans (F7b's
  `GET /partitions`); rebuilding `partition.json` from `ns.json` and
  re-adopting a lost uid are F5's/F2's (the records and
  `adoptablePartitionUID` are here); `DeploymentDiskStatus`/`/tile-status`
  per partition (F2's route class).
- **Tests:** `TestNsKeysPartition`, `TestNoAdHocResourceKeys` (extended),
  `TestPartitionReachTable` (policy off/on/consented),
  `TestPartitionReachPaused`, `TestPartitionKVRoundTrip`,
  `TestPartitionBlob`, `TestPartitionEnv`, `TestTileHoldsDataPartitions`
  (and the wipe), `TestPartitionOrphanRules`, `TestPartitionIdleKVClose`
  (broker); `TestSharedBindNeedsRegistryShared` (runner);
  `TestPartitionVolumesInitConcurrently`, `TestPartitionVolumeIdleUnmount`,
  `TestPartitionDirKeys`, `TestPartitionVolumeRoundTrip` (resenc, the last
  with real FUSE); `TestNoPartitionGolden` extended (no `.partitions`
  level, no `partition` on resource rows, in the zero state).
