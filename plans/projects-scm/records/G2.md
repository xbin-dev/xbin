# G2 — scm-github events

> Status: live — branch `wp/ps-g2` (from `projects-scm` at `7dda955d`).

## What was built

- **Receipt** — `G/_backend/hook.go` (projects-scm §5.10.1):
  `POST /hook/github` at global or legacy (a partition: 404), from
  ingress or a manager testing; body ≤ 8 MiB; `X-Hub-Signature-256`
  in constant time against `app-webhook-secret` and, for 24 h after a
  rotation (`hook-secret-rotated`), `app-webhook-secret-prev`; no secret
  → 503 `setup`; a bad signature → 401, counted, and recorded for
  `events.healthy`. `ping` → 200. A delivery whose account
  (`installation.account`, else the repo's owner, else the organization)
  isn't in `allowedAccounts` is dropped **before** dedupe and
  normalisation (202, counted). Dedupe on `X-GitHub-Delivery` per
  installation (`seen/<installation>/<delivery>`, 7 days, ≤ 10 000 each,
  pruned daily or when an installation's set grows by a tenth), with an
  in-memory guard so one delivery arriving twice at once is taken once.
  `installation` events refresh `inst/` (and drop the repos list cache);
  `member`, `membership`, `organization` and `installation_repositories`
  drop the `access/` entries they touch; none is forwarded. Everything
  else is normalised, matched and queued, 202 at once; a queueing failure
  answers 503 and isn't marked seen (a redelivery is taken).
- **Normalisation** — `G/_backend/normalize.go`, `normalize_gh.go`
  (§5.10.2, the table of docs/scm.md §Delivery): `pull` (merged, ready,
  draft mapped), `checks.completed` (a completed check suite, a final
  commit status), `check`, `workflow` (a `workflowRuns` entry without
  jobs), `job` (`{runId, job}` with its steps), `comment` (issue and
  review comments, `path`, `line`), `review`, `push` (`forced`; tags are
  no event), `issue`. Topic, ref, actor (five associations; `self` = the
  App's `<slug>[bot]`), summary in the provider's own words (numbers,
  logins, branches, shas — never a title or body), `eventId`
  `scm:<host>:<delivery>[:<i>]`. Every field from the body is checked
  (repo, login, sha, branch by git's rules, http(s) URL without
  credentials); text is clipped (bodies 8 KiB, check output 4 KiB),
  control characters dropped, token shapes redacted. A suite and a
  final status of one commit within 5 s are one `checks.completed`
  (every one is held 5 s; the worse conclusion, both halves' runs).
- **Subscriptions** — `G/_backend/subs.go` (§5.10.3, §5.6):
  `POST|GET|DELETE /scm/subscriptions` — a tile at global or legacy
  (`for: global`; the bot must see the repo: `withAuth` as the bot, so
  `allowedAccounts` and `botRepos` hold, then `GET /repos/{o}/{r}`); a
  person's consumer in their partition relays (not signed in: 409
  `signin` with a flow started) to `POST|GET /partition/subscriptions`,
  `DELETE /partition/subscriptions/{id}` at global, which re-checks the
  body (consumer one of global's `agents` bindings, never a personal one;
  the repo in `allowedAccounts`; the person's `ident/<user>` login — none:
  409 `signin` — able to read it per the collaborator permission API with
  the installation token: `none` 403 `not-allowed`, unseen 404) and keeps
  `for: user:<id>` with the caller's partition id. A person's consumer at
  legacy: 403 `identity`. Key replaces (200, same id); 30-day expiry;
  2000 per consumer and `for`, 20 000 in all. Matching: repo; kinds
  (`kind` or `kind.action`; none = every kind but the progress ones);
  `branches` (exact), `prs`, `issues: true` when named; a tile's also
  `botRepos` at match time.
- **Outbox and delivery** — `G/_backend/outbox.go`, `deliver.go`
  (§5.10.4, §5.10.6): `outbox/<id>` per (event, consumer, `for`), ids
  sorted by queue time; a worker (a goroutine woken by new items, and the
  `tick` cron) POSTs `/adapter/scm/event` through the `agents` binding
  whose `provider` is the consumer, a consumer's items in order, four
  consumers at once, a failing consumer's other due items held with it. A
  person's item: dropped unless `ident/<user>` still has the
  subscription's `pid`; for a private repo their access is re-read
  (`access/<login>/<repo>`, ≤ 1 h): `none` (or the repo unseen) drops it
  and deletes that person's subscriptions on the repo. A
  `checks.completed` of a suite gets the suite's runs from GitHub before
  its first attempt (best effort). 200 delivered, 404 dropped and counted,
  else 10 s doubling to 1 h, dropped after 24 h. The `tick` cron (`@every
  1m`, `res:<self>/tick`, path `/tick`) is registered while an item is
  pending and removed when none is; at start, deliveries GitHub failed
  since the last that arrived are redelivered (`GET /app/hook/deliveries`,
  ≤ 50, never one seen). `GET /scm/events?since=&repo=&limit=&cursor=`:
  a tile's at global, a person's relayed (`GET /partition/events`), 7
  days, oldest first. `wipePerson` drops a person's subscriptions and
  items (Forget, a new partition id).
- **Events health** — `evHealth` fills G1's `eventsHealth` seam (§5.10.5):
  `active` while the App's hook URL is set and a delivery or ping arrived
  in 24 h, `inactive` while it is unset, else `unknown`; `healthy` = active
  and no bad signature in the last hour; written to state
  `events-health` and conf `events` (people's partitions read it) when it
  changes, at most once a minute for times. `GET /api/events` (managers):
  health, counts, outbox and subscription totals.
- **Mounting** — `hook.go`'s `init()` fills G1's seams (`extraRoutes`,
  `extraCaps` → `events`, `eventsHealth`, `tickHooks`, `wipePerson`);
  `main.go` calls `startEvents(true)` (one line) and its header names the
  files.
- **The fake GitHub's webhook side** — `G/_backend/fakegh_hook_test.go`:
  signed deliveries with the secret setup gave the fake's hook config,
  fixtures with fields changed, fake consumers answering queued statuses,
  the cron log; `GET /app/hook/deliveries` and redelivery through the
  fake's existing injection. Fixtures `G/_backend/testdata/*.json` (16,
  each < 5 KB, acme/octocat only).
- **Docs** — scm-github `API.md` §7 (and lines in §1, §10, §11, §12),
  `AGENTS.md` (the files, the rule for webhook bodies); docs/scm.md
  §Events: two fixes (below).

## Seams for others

- **E (and V)** receive event v1 exactly as docs/scm.md §Delivery: at the
  consumer's `/adapter/scm/event`, `X-XBin-From` = the provider's tile
  path, from the provider's global instance; `for` `global` or
  `user:<id>` with `forPid`. Answer 200 (taken or duplicate) or 404; any
  other status is retried. `subs` lists the matching subscriptions' keys
  (a keyless one by its id).
- E's subscriptions (§11.2) work as posted: `{repo, branches, prs, kinds,
  key}` and `{repo, issues: true, kinds: [issue], key}`; re-posting the
  key keeps the id and resets 30 days.
- Differences E should know: a pull request or workflow run from a
  **fork** has no `ref.branch` (`data.pull.head.repo` names the fork); a
  commit status's `ref.branch` is the branch a subscription matched (a
  status names every branch whose head the commit is); a status's run id
  is `status:<context>`; every `checks.completed` reaches a consumer at
  least 5 s after GitHub sent it; `check.in_progress` is GitHub's
  `created` of a run already in progress.
- Hello's `caps` now list `events` in every mode.

## Changelog text

- builtin-templates: **scm-github delivers events.** GitHub's webhooks
  reach the global instance (`bx expose apps/scm-github hooks=… --host
  …`), signed with the App's webhook secret (the previous one still taken
  for a day after a change), and become the scm contract's events — pull
  requests, CI (suites, statuses, check runs, workflow runs, jobs with
  their steps), comments, reviews, pushes, issues — delivered to the
  tiles bound in its `agents` slot that subscribed
  (`POST /scm/subscriptions`), retried for a day, and listed for catching
  up (`GET /scm/events`, seven days). A person's subscription is theirs:
  made from their partition, checked against their own GitHub access, and
  re-checked before an event of a private repo reaches them. Deliveries
  for accounts the policy doesn't serve are dropped; hello's
  `events.webhooks`/`healthy` say whether webhooks are arriving.
- docs: scm.md §Events — `subs` names a keyless subscription by its id;
  `GET /scm/events` pages with `cursor`, oldest first, `since` in Unix ms.

## Decision text

- **Webhooks at global, delivered through an outbox** (GitHub never
  retries a failed delivery): one item per (event, consumer, `for`),
  retried with backoff for a day, a cron registered only while something
  waits, a start-up catch-up through GitHub's delivery log. Not chosen:
  forwarding synchronously (a consumer down loses the event).
- **Foreign accounts dropped first:** a public App can be installed by
  anyone; their deliveries are dropped before they can fill the dedupe set
  or the outbox. The account is the installation's, else the repo's owner
  (repo events carry no installation account).
- **A person's events stay theirs:** subscriptions only through their own
  partition's relay, kept with their partition id; delivered only to a
  tile bound in `agents`; for a private repo, their access re-read (cached
  an hour, dropped by GitHub's access events) before each event — lost,
  their subscriptions there go. Public repos aren't re-checked (anyone
  reads them).
- **Fork branches aren't this repo's branches:** a fork's pull request or
  workflow run names no `ref.branch`, so a subscription (or a consumer
  routing by branch) never mistakes a fork's same-named branch for its
  own. Not chosen: passing GitHub's head ref as is.
- **A suite and a status within five seconds are one `checks.completed`**
  (the worse conclusion): every one waits five seconds. Not chosen:
  suppressing the second (a failure could hide behind a success).
- **Untrusted text redacted as well as clipped:** token shapes in bodies
  and CI output become `[redacted]` — the provider otherwise never
  interprets text.

## Owner questions

- **Fork branches.** A fork's pull request or workflow run names no
  `ref.branch` (fail closed: a fork's same-named branch never routes to a
  task). Built: that. If big tasks (P2) ever push to a fork of the repo,
  E would match them by pull request number only — which it does first
  anyway.
- **A tile's subscription without an `agents` binding** is accepted and
  its events retried for a day, then dropped. Built: accept (the binding
  may come after). The alternative is 400 `invalid` at subscription time,
  as for a person's.
- **Redaction in passed-through text.** Token shapes in comments, bodies
  and CI output are replaced by `[redacted]` before an event leaves; the
  contract says a provider passes text through. Built: redact (a leaked
  token in a comment shouldn't travel further).
