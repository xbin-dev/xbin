## Review (the S0 revise)

Three adversarial reviews of the first freeze (security, partitions and
credentials; buildability and the WP split; compat, upstream and docs):
**49 findings — 8 blockers, 19 majors, 22 minors. All 49 fixed; none
rejected.** 12 were already fixed by the interrupted first revise (kept
as a WIP commit and checked finding by finding), 37 were finished here.
Skeptic verifiers then re-checked every finding against the tree and
found 13 gaps and 7 new inconsistencies; all 20 were fixed in a last
round. The chief changes:

- **Authority over the bot** (blockers sec#0, sec#1): V15 — where a
  home's identity is the bot (a partitioned agent's global, an
  unpartitioned agent), naming a repo takes a manager or the scm bot rule
  (`scmBotAllowed`, `GET|PUT /projects/scm/bot`, kept in that home's
  settings); a partitioned global holds team definitions only; every
  route and tool reads only its project's repos; CI ids must come from the
  watch's snapshot; rerun is a person's own (V12). The credential gate
  (§9.2) no longer trusts `homedHere` outside partitions nor the
  project's own label: a sandbox homed at its owner's own global
  identity, every user of it a participant (`projectLevelOf`, fail
  closed).
- **Team projects** (blockers sec#2, sec#3): V16 — a membership clones the
  team's seed only when it works as the bot; a person's token never
  enters a seed or a seed clone (`from_seed`). V17 — a membership runs the
  definition's security-relevant part only as its member accepted it
  (`def_hash`, `def_pending`, `POST /memberships/{pid}/accept`, `GET
  /memberships/{pid}/pending`).
- **The coordinator** (sec#5): V18 — project tasks never run in a class
  with internal reach; P1 strips it in `classState.classOf` itself.
- **Buildability** (blockers bui#0–bui#3): `projectDeliverHook` and its
  call site; the `refs` job finds an agent's own pushes and PRs and fires
  `projectRefsHooks`; `turnEndHooks` at all four turn ends incl. a child
  coding agent's and the cancel path; native CI moves from U2 to V so no
  wave-2 WP imports another's files. Majors: `runStatusHooks`,
  `runViewHooks` (the CI chip's first state), `ownerLoops`,
  `scmCredsDue`, `scmPendingSignin`, `projectTaskChanged`,
  `projectRefsCheck`; K no longer edits `harness_engine.go`.
- **Compat and docs**: E's intake route mounts through
  `adapterRouteTables`; feature schemas never run on the team database
  (`addFeatureSchemas`, `DB.features`); the changelog draft states the
  rollback honestly; the scm-github `partitionNote` says what a mode
  switch removes; two more docs rows (workspace-template AGENTS.md,
  docs/partitions.md); a §16.6 landing gate (no staged keys or
  "Described when it lands." left); D158 → D172 where coding agents at
  global are meant; §18's "run as root" line now cites upstream ACP
  (`CreateTerminalRequest` has no user field) and that AgTT advertises no
  client terminals (`harnessCaps`).
- §14.1 and §14.3 are again verbatim copies of `projects_seams.go` and
  `scm_types.go` (checked by diff).

Found on the way: `hack/tile-check.sh` word-splits `TILE_TEST_FLAGS`
without re-parsing quotes, so `-run 'X'` matches nothing and passes
having run no test. The first freeze's targeted seam-test row was such a
no-op (its full tile-check run was real). §15.3 now says to pass the
pattern unquoted and with `-v`.
