## What was built

## Decision text

- U2's model lives in three new modules made on first use that wrap
  `app.projects.take` once, rather than in `model/projects.js` (at its
  900-line limit) or `model/app.js` (U1's, then V's): no hot file grows.
- "Work on this" learns the definition's security part and hash from the
  409 of a first `POST /memberships` sent with nothing accepted, and
  accepts exactly that hash: no other route answers it (§7.2), and the
  member sees the server's own security part — never one the page
  reconstructed — before anything runs in their sandbox. Not chosen:
  computing the hash in the page (it would have to match the backend's
  canonical JSON exactly).
- A team board row opens only for its own member, from their own
  partition, for a run id ≥ 2^40 and a member still on the board; every
  link drawn from a board row or an event is `https` only (stricter than a
  task's own chips, which come from the member's own provider); text from
  either is plain and clipped — fail-closed, as §12.3 asks of global.
- On the web U2's surfaces register no seams of their own beyond `sbx`:
  `projects.js` draws `project-feed.js` and `project-team.js` (U1's
  `project-web.js` U2 slot stays empty).
- Natively, `app.page 'projects'` is followed onto the screen stack (the
  list, and the project the model has open), and the stack going back to
  a projects screen opens what it shows again — so `#proj`/`#proj=<id>`
  and the saved place follow the person; a task conversation opened from
  the board leaves the page, as on the web.
- Natively a task's chips are one toolbar menu titled with its PR (or
  branch), with Open PR inside: a phone's bar holds few items.
- The seed sandbox of a team definition and "Fork base now" are drawn
  although §13 doesn't name them: their routes (T's `seed`, P2's
  `fork-base`) need a person (the fork base "only after the person
  confirms"), and a definition made from a person's own space has no
  other way to get a seed.

## Fix round 1

A skeptical verifier's six findings, each checked against T's handlers as
built on `wp/ps-t` (`_backend/project_team_member.go`, read only). All six
were real; all are fixed, each with a check that fails without its fix
(the five new node tests fail 5 of 5 on the old views; the browser run
fails on the first new check).

Fixed:

- **(major) Work on this with no seed got T's 400.** T's `POST
  /memberships` makes a sandbox with no `sandbox` in the body only from
  the definition's seed, and only when a manager bound in the member's
  space serves it; a definition made from a person's partition never has
  a seed, so Continue → 409 → Accept and start → 400. Now the body is
  `{ref}` (one of yours), nothing when a bound manager serves the seed (T
  forks it), else `{new: {provider}}` from a manager picker (web

  set — which only a sync sets. Now `app.projects.open` (wrapped once, as
